# KEEP IT LIT - feature-specific gotchas

Moved out of CLAUDE.md on 11 Oct 2026. The general gotchas stay in CLAUDE.md; these are the ones tied to one feature or art pack.

- **The escape hatch is a kit template too (F80).** `InteractableKit.escapeHatch` (optional slot, built by **KEEP IT LIT > Build > Interactables**) is a double-leaf trapdoor made of two Alchemist `WoodDoor01` leaves over a `Glow` slab. `MazeEscape.BuildHatch` clones it, gives `Glow` the runtime `HatchGlow` material (so `ApplyLockLook`'s green/red still works) and swings the `LidL`/`LidR` children about their local Z: shut while padlocked, ajar (16°) once usable, thrown open (100°) on entry. With the trapdoor present, stepping on the hatch runs `MazeEscape.EnterHatch` instead of the instant `CompleteEscape`: freeze, leaves open, the player eases over the opening looking down (0.75 s), then `FloorCleared` starts the blackout while they are lowered `dropStartDepth` through it (0.45 s); `_entering` holds the timer and trigger meanwhile, and the routine bails if a capture starts first. A black `Pit` inset makes the open hatch read as a hole. Empty slot = the old glowing slab and instant drop. The exit gates (F111) are the kit template `InteractableKit.escapeGate` (not optional: `ProjectSetup.EmptySlots` flags it; built by `InteractableKitBuilder.EscapeGate.cs`, primitives and the kit materials, never null). **Name contract**, found by name: `PostL`/`PostR`/`Lintel` (colliders), `Shutter` (slats + one solid box over the opening, moves up ~3 m), `LeverBox` (`GateLever` is added to it at runtime) with `LeverFocus` (solid box collider, hit by `PlayerInteractor.Probe`, which stays focusable for an `IProgressInteractable` even when `CanInteract` is false so the prompt can say NO POWER/LOCKED) and `LeverHandle`, `Lamp0`-`Lamp2` (a `Bulb` renderer and a disabled `Light` each), `Chain`, `Stairwell`, `StubLight`; local +Z points into the maze. The lever hold is **non-resetting**: `IProgressInteractable.HoldTick` is driven by `PlayerInteractor` and never decays, unlike `HoldSeconds`. `MazeGenerator.ChooseGates` checks the kit slot and theme **before** the walls are built (a missing slot keeps the hatch; a hole must never be left in the wall), and `ReserveGates`/`IsLayoutReserved` keep props off the cells.
- **`MazeDoor._open` is intent, set when a slide starts, not when it ends.** It used to flip only at the end of the slide coroutine, so mid-slide every reader saw a stale value: `CheckBash` re-bashed a door that was already rolling up every frame (restarting the slide and renewing `AIFollower.Stall` forever — the hunter froze for good in front of a shutter that looked open), and `Unlock`/`AllStarsCollected` arriving while a bashed door rolled back down did nothing and left it shut but `_permanentlyOpen`. The physical state is the panel offset (`_blocker.enabled = _panelOffset < 2`). Doorway-occupied checks read the whole `DoorBreakers` registry (`BreakerInDoorway`), so a shutter never closes on the Stalker either, and a bash-hold that expires with someone in the gap retries every 0.5 s instead of giving up.
- **F74's new statics follow the same reset rule.** `RunRules` (current rule/name/description/multipliers) and `LoreArchive` (read note ids) both have a `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` reset; `LoreArchive` is also cleared in `GameFlow.ReturnToMenu` (campaign-scoped, like `PlayerWallet`) while `RunRules` is recomputed every floor by `ApplyFloorProfile` regardless (still cleared there too, for cleanliness). `ThrowController`'s carried count and `Lantern`'s carried state are deliberately **not** statics — they're instance fields on components a scene reload naturally recreates, which is what makes them reset "for free" without touching this rule.
- **F87's statics follow the same reset rule.** `ContractState` (active contract, floor, the two offers, salesman line) has a `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` reset and is cleared in `GameFlow.ReturnToMenu`. It is saved in `SaveData` as `contractActivePlus1` / `contractFloor` / `contractOfferAPlus1` / `contractOfferBPlus1` (ids stored +1, so a pre-F87 save - fields missing, read as 0 - means "none"; `SaveSystem.Version` was not bumped). `GameFlow.IsInIntake` is reset in `Reload`, `ResetStatics` and (through `Reload`) `ReturnToMenu`; `IntakeRoom.Active` is a scene-scoped reference cleared in `OnDestroy`. `ContractTracker` and `ThrowController`'s carried count are instance state and reset by a scene reload; its three static-event subscriptions (`LoreNote.Read`, `Stalker.PlayerTouched`, `ThrowableItem.HunterInvestigated`) unsubscribe in `OnDestroy`.
- **`FloorProfile.Objective` is a flag set now (F77), not the single `FloorObjective` value it used to be.** `Objective.Stars` is gone — stars are always present — so test a mechanic with `profile.Has(Objective.Lockdown/Blackout/KeyHunt)`, never equality against `Objectives`. `GameFlow.RolledObjectives` (the previous floor's rolled pair, so two consecutive floors never repeat) follows the same static-reset rule as everything else in the first Gotcha above: reset in `ResetStatics` and `ReturnToMenu`. `RunRules.HashSeedFloor` is `internal` (not `private`) specifically so `FloorProfile.RollObjectives` can reuse it with its own salt — the two rolls are deliberately independent draws from the same seed, not the same draw read twice. `+18` is `BuildKeys`' RNG offset — the next free one is `+19`. The padlock itself (locked hatch or gates, red glow, wayfinding retarget to the nearest missing key) lives entirely in `MazeEscape`, not in `GameOutcome` or `GameManager`.
- **Alchemist House dressing (F79).** 31 composed `PropPiece` prefabs built from `Assets/BK_AlchemistHouse` live in `Assets/SourceFiles/Themes/Common/Prefabs/Alchemist/` (`Alch_*`: 17 collider-less floor clusters, 4 standing wall props with one root `BoxCollider`, 7 hung wall props, 3 rugs as `FloorDecal`s). They plug into the existing `BuildFloorProps`/`BuildWallProps`/`BuildDecals` passes — no new pass or RNG offset. Each theme's subset (`ThemeSets`, an `AlchemistSet` flags enum, in `FloorThemeBuilder.Alchemist.cs`) is added by the full **Build > Floor Themes** rebuild (the one-off *Add Alchemist Dressing* migration has been applied and removed). `AlchemistPack` (`Assets/Editor/AlchemistPack.cs`) holds the pivot-agnostic spawn/strip/place-by-bounds helpers — pack pivots and root scales are unreliable, so never place a pack piece by `transform.position` or set its `localScale`. **KEEP IT LIT > Build > Re-skin Templates > Bottle, Can, Lantern, Candles, Note** re-skins those `InteractableKit` slots with pack models (primitive fallback if the pack is missing); `InteractableKit.bottleVariants` are look-alike bottles `BuildThrowables` picks by a hash of the cell, deliberately **without** an `rng` draw so the +13 stream is untouched (a thrown bottle still uses the base template). The primitive lore note's quads face the wall (a Quad renders only from −Z, and `BuildLoreNotes` points +Z into the corridor); the book note's glow edge is flipped to face the corridor. Spec: `plannings/alchemist-maze-dressing-plan.md`.
- **Pack dressing (F85).** Every fitting art-pack piece is spread over the floors (spec `plannings/pack-dressing-plan.md`). Defined in `FloorThemeBuilder.Pack.cs` (partial): **Alchemist furniture** (`FurnitureDefs`: 3 cupboards, 3+1 drawers, long table, workbench, sink, stove, hung shelf with bottles, a nursery floor cluster of the pack's babies — new `AlchemistSet` flags `Cabinets/Shelves/Tables/Workshop/Sink/Stove/Alembic/Nursery`, per theme in `ThemeSets`; standing ones are wall props with one root `BoxCollider`, shrunk at most 15 % to fit the 0.68 m depth — `ComposeFurniture` leaves a piece out and logs rather than squash it, which is why Alembic02 (0.81 m deep, 18 % shrink) is not in; table03 and Table04 are 1.45 m and 2.06 m square and were never defined), **DeadBody LITE** (`PackDef`: `Pack_MorgueBed` Ward/Lab, `Pack_EmptyBed` Ward/Crypt/Hollow, `Pack_BloodyBath` Ward/Crypt/Hollow — set pieces up to 1.3 m deep; `Pack_StandingShroud` Crypt/Hollow wall prop, **`enabledInMaze` off** (7 Oct 2026: reads as the hunter in the dark; kept in the gallery for a future idea — `PackDef.Enabled`); `Pack_HangingBody` Crypt/Hollow ceiling prop) and **Socket Pack** (`Pack_AirVent` high, `Pack_Socket` low, `Pack_FuseBox` decor, hung wall props at ×2–2.5 scale with the glass door hidden). Look-alike models are children behind a `ModelVariants`, picked by a hash of the cell (`MazeGenerator.ApplyModelVariants` for wall/ceiling props, as for set pieces) — never an rng draw; no new RNG offset. The pack's `[ExecuteInEditMode]` scripts (`BathTub`, `DeadBodyHanging`) are applied once at bake and removed; rigidbodies/colliders are stripped and a fitted `BoxCollider` added per variant. **Floor 5 borrows the Crypt theme row** (`FloorProfile.FloorThemes`; the user keeps it that way — the Hollow row never plays, so the Crypt row also carries the Hollow-only pieces: `Stove`/`Nursery` in `ThemeSets[2]`, the empty bed and bloody bath in their `PackDef.Themes`) at 4.0 m while floor 3 is 3.2 m, so `Pack_HangingBody` carries a `HangingBodyFit` per variant and `BuildCeilingProps` calls `Fit(wallHeight)` (lengthens the rope, drops the body; feet about 0.4 m off the floor; `PropPiece.AllowLowHang` skips the low-ceiling depth guard). `PackMaterials` (shared `UrpCopyOf`, also used by `InteractableKitBuilder`) gives the Socket Pack's Built-in materials URP copies. **`PackDressing`** (`Assets/Editor/PackDressing.cs`) appends what a gallery row lacks (props *and* set pieces, as showcase instances) without rebuilding; `NeedsUpgrade`/`Apply` run from the end of Build > Floor Themes and from a `ProjectSetup` Piece. `BloodDecalUpgrade` now also turns every `*_DragMarks` into blood-pack smears (blood4–7, free roll) and re-skins the FallenRunner's baked `DragMarksDecal` (Crypt_Collapse's dust quad stays). **Density:** `MazeGenerator.propDensity` (default 1.4) scales the theme's wall/ceiling/floor prop chances (cap 0.85, never below the theme's own) and `setPieceBonus` (default 1) adds a set piece on themed floors — dressing streams only. The packs are git-ignored: `/Assets/Socket Pack/` and `/Assets/Gabies_Assets/` joined the ignore block, and the DeadBody LITE meshes/materials/textures the new prefabs use were force-added.
- **Surface textures (F88).** The structural theme materials (walls/floors/ceilings of Ward, BoilerDeck, Crypt, Lab — floor 5 is the Crypt row) carry real PBR sets: ambientCG CC0 1K sets in `Assets/SourceFiles/Textures/PBR/<AssetId>/` (Tiles107, Tiles074, OfficeCeiling001, MetalPlates004/011/013, MetalWalkway014, Concrete033) and, for the Crypt, three Ultimate Material Library textures (`Assets/GreenMossGames/…/Textures/`, Poly Haven CC0 scans; the 2.8 GB library is git-ignored and only the used PNGs are force-added; its own materials are Built-in and unused). `ThemeSurfaceUpgrade` (`Assets/Editor/`, idempotent, table of material → set/tiling/tint/normal/smoothness) edits the `.mat` assets in place, bakes `<AssetId>_MetalSmooth*.png` (R = metalness × MetalScale, A = 1 − roughness — keep the Roughness/Metalness jpgs, they are the bake input), runs at the end of Build > Floor Themes and is a Check Project piece. Tints were lowered so tint × albedo stays near the old colour (F71 darkness balance). Pillars outside the Crypt share trim materials, so they are not textured yet. Credits: `Assets/SourceFiles/Textures/PBR/CREDITS.md`. Spec: `plannings/surface-textures-plan.md`.
- **No untextured primitive dressing (F89).** Every decorative prop and set-piece part built from Unity primitives with plain materials was removed from the maze rows (Papers, Debris, Bucket, Bottles, the Ward medical props, Boiler barrels/pipes/gauges, Crypt rubble/bones/chains/roots, Lab racks/tanks/cables, Hollow cloth/doll props, the Ward_Triage / Ward_Isolation / Crypt_Collapse / Boiler_Burst / Lab_Containment / Lab_Desk / Hollow_Nest set pieces, and the drain/grate/seam/pipe/tray decor on the structural tiles). Pack stand-ins: `Alch_CrateStack` (Boiler), `Alch_Candles` (Crypt, Hollow), `Alch_Urn` (Crypt), `Alch_SpecimenShelf` + `Alch_Board` (Lab) are new `AlchDef`s in `FloorThemeBuilder.Cleanup.cs` behind new `AlchemistSet` flags; `Crypt_Shrine`, `Boiler_Sparks`, `Hollow_Circle` and `FallenRunner` keep their lights/decals but their primitive parts are pack models (`Dress*` helpers in the same file, used by the builders and by the migration). `PrimitiveDressingCleanup` (`Assets/Editor/`, idempotent, no menu item, runs at the end of Build > Floor Themes, flagged by Check Project) brings an existing scene to that state and holds the removed-name tables. Still primitive on purpose (gameplay): lockers, wall lamps, stars, shards, `NoisySurface` glass/puddle patches and every other `InteractableKit` template, structural wall trims and pillars. Do not add primitive decor back; build from a pack model or leave it out. Spec: `plannings/primitive-cleanup-plan.md`.
- **The last untextured pieces (F90).** Wall prefabs carry no decorative trim any more (Ward dado/skirting/cornice/pillar cap, Boiler rivets/pipe/flanges, Lab cable tray/cables/seams are gone; the Crypt ledge is textured and stays) and the Ward/Boiler/Lab pillar bodies use their own `<Theme>_Pillar` material (the wall's set at tiling 0.42 x 2, created from the wall material by `ThemeSurfaceUpgrade` when missing). `ThemeSurfaceUpgrade` also textures the fixture metals/wood (lockers, lamp housings, shutter, bell, valve, lever, battery, terminal case, key hook) from the GreenMossGames library with a constant `Metallic`. `InteractableKit`: `glassPatch`/`puddle` are a root `NoisySurface` with a `Look` decal quad (`NoisePatchLook`: a drawn shard texture `Textures/Decals/GlassShards.png` and a rounded `PuddleMask.png`, transparent URP Lit, `_BlendModePreserveSpecular` 0; `NoisySurface.Configure(diameter)` scales `Look` for a shatter patch, the trigger is unchanged); `loreNote` is a pack `WoodShelf01` with `Book12` leaning on it, one root `BoxCollider` and a `Glint` point light pulsed by `StarPulse` (which now picks up a sibling `Light` in `Awake`); new slot `shardModel` (pack `Bulb01` lump) that `MazeGenerator.BuildShard` clones as the shard body (still exactly one `rng.Next(360)`, glow material `Maze_ShardModel`), cube fallback if the slot is empty. The Intake's note is a plain clone of the template, so `RemainingPrimitivesCleanup` (no menu item; run by Build &gt; Floor Themes, flagged by Check Project, a ProjectSetup Piece) re-clones it. Spec: `plannings/remaining-primitives-plan.md`.
- **F92 statics.** `GameFlow.IsInHub` (set by `AsylumHub`, cleared when the wing door hands over) and `GameFlow.ArriveInHub` (set only by `NextFloor` and CONTINUE from a floor-start save through `Restart(.., viaHub: true)`; every other `Restart` clears it) follow the usual rule: reset in `Reload`, `ResetStatics` and `ReturnToMenu`. `AsylumHub.Active` is scene-scoped (cleared in `OnDestroy`), and the hub restores the floor's `RenderSettings` in `OnDestroy` too. Pack TGA/PNG sources are shrunk in place (`AsylumMaterialUpgrade.ShrinkSources`), so re-importing a pack needs that run again. The `AsylumShot.cs` dev helper is deliberately untracked. **`GameFlow.ShopFromHub` (F94)** is transient (never saved): reset in `Reload`, `ResetStatics` and `ReturnToMenu`, set by `AsylumHub.ShopWalkInRoutine` before `ArrivePlayer`, cleared by `ReturnFromShop`.
- **F93 gotchas.** (1) The agent type **"Hub"** exists once (`HubNavMesh.EnsureAgentType`, looked up by name); the hub NavMesh is baked in the editor to `Assets/SourceFiles/NavMesh/AsylumHub_NavMesh.asset` — after adding colliders to the hub run `HubNavMesh.Bake(hub)` (`AddStoryLayer` does it when it adds pieces). (2) `+19` is `BuildPatientFile`'s RNG offset; `+20` is F103's dead-end keep roll (`RemoveDeadEnds`); F105 uses `+21` (C2 rooms/gallery) and `+22` (C3 squeeze) and reserves `+23` for C4 (loop corridor), and F107 uses `+24` (DESCENT item caches) and `+25` (entity placement: the Listener, the Tenant, the living bodies), so the next free one is `+26`. (3) `HubState.IsFinale` is the only new static (reset in `ResetStatics` and `GameFlow.Reload`); `ThirdPersonController.SpeedMultiplier` is an instance property a scene reload resets. (4) Mixamo "Standing Up" character FBXs rest in a lying pose: never place bone children from their edit-time pose (`HubStalker.FitEyes` re-poses to the avatar T-pose at runtime) and set emission black on their extracted materials (the pursuer's was white). A near-black albedo still reads grey under the torch through sky reflections: `Subject_Ch45_Body` has smoothness, specular and environment reflections off. (5) A set piece or `Life` child must not hold a `Light` that `HubDecay` could re-enable (decay skips everything under `Life`); lights count toward the 56 budget when enabled. (6) A `MonoBehaviour` message (`OnEnable`/`OnDisable`) redeclared in a subclass hides the base's — `HubSetPiece` makes them `protected virtual`. (7) Prefab applies reorder the YAML (a big textual diff that is semantically additive); check with names/counts, not `git diff --stat`. (8) Never edit scripts while Play is running with the hub (domain reload leaves `AsylumHub.Active` empty); the Unity window must be foreground (`SetForegroundWindow`) for frames to advance in tests.
- **Recorded audio (F97).** The generated sounds (`DoorAudio.Build*`, `AngelAudio`, the `AudioClip.Create` loops) are only fallbacks now: `GameAudioLibrary` (`Assets/SourceFiles/Audio/GameAudioLibrary.asset`, one `AudioSlot` per sound: clips, loudness trim, pitch jitter, start offset, max seconds, low-pass) is assigned to `MazeGenerator.audioLibrary` and exposed through the static `GameAudio` (`Library` is never null; `PlayAt`/`Play2D` return false on an empty slot, so a call site reads `if (!GameAudio.PlayAt(GameAudio.Library.x, pos, vol)) generated...`). Variations use `Random.Range`, never a maze rng stream. Filled by `GameAudioLibraryBuilder` (+ `GameAudioImport`: Vorbis 50 %, mono for 3D one-shots, long loops streamed) through the ProjectSetup piece "Audio library" - it never overwrites a slot you edited; a slot left empty keeps its generated sound. Packs: `Assets/Free Pack`, `Assets/Horror Elements`, `Assets/Libraries/Soundbits_freeSFX_2025` are git-ignored; only referenced clips are force-added. Files that end in silence (`Amb_darkroom`, `Misc_breath`) are restarted with a fade, not looped. `MazeGenerator.logAudioResolution` logs each library clip the first time it plays. Slots still generated: wind, lamp buzz, lift motor hum, Stan shriek, reception bell, call bell, shop door, escape ping, heartbeat, hunter hum/choir, creature blips. Spec: `plannings/audio-wiring-plan.md`.
- **Saves persist `ShopItem` as ints (F83).** Append new `ShopItem` values, never reorder or remove them, and bump `SaveSystem.Version` whenever `SaveData`'s meaning changes (a mismatch discards the save). `GameFlow.ResumeInShop` is a static and follows the usual reset rule (`ResetStatics` + `ReturnToMenu`). Any new campaign-scoped static also needs a field in `SaveData` and a `CaptureTo`/`RestoreFrom` pair, or CONTINUE silently drops it. **`HunterMemory` (F105 C6) is the newest one:** a `SubsystemRegistration` reset, cleared in `GameFlow.ReturnToMenu`, and five `SaveData` fields (`hunter*`) that default to 0 in an older save (hence no `Version` bump). F105 campaign statics follow it: `HunterMemory` (levels + pending mask) and `LoopCorridor.UsedThisCampaign` (`SaveData.loopCorridorUsed`, set by `GameOutcome.FloorCleared`, `SubsystemRegistration` reset, cleared in `GameFlow.ReturnToMenu`, no `SaveSystem.Version` bump: an older save reads false = the loop may still appear).
