# KEEP IT LIT — Detailed Gotchas, Non-Game Assets & Project Memory

## Gotchas That Bite (Unabridged)

- **Statics must survive a scene reload and must not survive Play mode.** `GameFlow` and `GameOutcome.IsOver` both have a `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` reset, because with *Enter Play Mode > Reload Domain* disabled a stale `SkipMenuOnLoad` would skip the title screen on the next run. `GameFlow.IsInShop`, `PlayerWallet` and `PlayerInventory` all have the same reset, and are also cleared in `GameFlow.ReturnToMenu` — the economy lives for one campaign only. `HubState.MealFloor` (F117, the floor whose free hot meal was eaten) is the same kind of campaign static as `HubCaches`: saved in `SaveData.hubMealFloor`, cleared by `HubState.ResetCampaign` in `GameFlow.ReturnToMenu` / `DescentRun` and at `SubsystemRegistration`. Any new static run state needs the same treatment.
- **`ShardPickup` is deliberately not a `Pickup`.** `GameManager.Start` counts `Pickup` objects as stars; a shard sharing that type would corrupt the star count and could fire `AllStarsCollected` early. **`ObjectiveToken` (F73) is the same idea for non-star objectives** (fuse boxes) — `GameManager` counts it alongside `Pickup`s in a second tally, so it gates `AllStarsCollected` too without touching the star count itself. **`KeyPickup` (F77) is neither** — a key never gates the hatch *opening* (it still opens on the last star/fuse exactly as before), only its *use*; the lock lives entirely in `MazeEscape`, not `GameManager`.
- **A `WallLamp.SetPowered(false)` lamp is not `IsDead`.** They're independent: unpowered just means dark-and-not-ticking-its-flicker right now (a Blackout floor before its fuse), `IsDead` means permanently killed (F27). `DreadDirector`'s kill waves/breath-blink and `PhantomDirector`'s lamp-blink phantom all check `IsPowered` too, or they'd waste a blink on a lamp that's already invisible. `Kill()` on an unpowered lamp is allowed and just waits — the fade plays once the lamp is powered back on.
- **Every static-event subscriber unsubscribes** in `OnDestroy`/`OnDisable` (`GameManager`, `MazeEscape`, `TensionDirector`, `HorrorAudioDirector`, `GameOutcome`). Restart is a plain `SceneManager.LoadScene`, so a missed unsubscribe leaks across reloads. Keep the pattern. `DoorBreakers` (F75) follows the same registry pattern as `LightPool`: scene-scoped, `SubsystemRegistration`-reset, and every registrant (`AIFollower.OnDisable`, `Stalker.OnDestroy`) unregisters itself.
- **`Time.time` is the run clock** and stands still at `timeScale = 0`, which is why run time is net of menu and pause. Don't swap it for `Time.unscaledTime`.
- **The cursor fight.** `StarterAssetsInputs` re-locks the cursor on every focus change, so anything showing a menu calls `PlayerLock.SetCursorFree(true)` *every frame*, not once. Freezing the player is three flags (`MovementLocked`, `LockCameraPosition`, `cursorLocked`) — always go through `PlayerLock.Freeze`.
- **Capture needs sight, not just distance.** A bare radius test captures through a wall (two actors either side of a 0.5 m wall are ~1.5 m apart), and `Update` still ticks at `timeScale = 0` behind the title screen — hence the `GameFlow.IsRunActive && _hasSight` gate in `AIFollower`.
- **`GameManager` counts stars at `Start`.** Anything spawning or removing stars after that desyncs the count.
- **Input System only** (`activeInputHandler: 1`). Keep the `#if ENABLE_INPUT_SYSTEM` guards in `ThirdPersonController` / `StarterAssetsInputs`. Since F119 every gameplay and menu verb is an action of `KeepItLitControls` read through `GameInput` and rebindable in Settings > CONTROLS > REMAP CONTROLS (Menu-map keys are fixed).
- **`Flashlight.IsDead` is no longer permanent (F71).** It recharges while off and can clear itself mid-run, so don't cache "the torch is dead" past one frame — re-read `IsDead`/`Charge` each time, the way `PlayerHud.UpdateBattery` already does.
- **A door is built post-bake with a collider and deliberately no `NavMeshObstacle` (F72).** The navmesh is already baked by the time `MazeDoor` exists, so a shutter can be any width the corridor needs — but it also means a `NavMeshAgent` has zero physics response to its collider and will silently clip straight through a closed door unless the door notices and opens itself (`MazeDoor.CheckHunterBash` + `AIFollower.Stall`). Any future door-breaker (F75's Stalker) needs the same self-detection; there's no `NavMeshObstacle` carve to lean on.
- **E has two owners now (F72).** `PlayerInteractor` (camera spherecast, `IInteractable`) is the default; `Locker` is the one holdout with its own E handling, and only because it predates this slice — new hideable/interactable things should implement `IInteractable`, not copy `Locker`'s pattern. `PlayerHud.SetFocusPrompt` always wins over `SetPrompt` while set.
- **New visible models are `InteractableKit` templates, not primitives at runtime.** Built once by **KEEP IT LIT > Build > Interactables** (`Assets/Editor/InteractableKitBuilder.cs`, build-missing-only by default so later slices can add their own slots safely); `MazeGenerator`'s various `Build*` passes clone them and log an error (naming the menu item) with no fallback if the kit or a slot is missing.
- **One MonoBehaviour per file, named after the file.** A component class declared inside another script's file (F86's `IntakeTarget` lived in `IntakeRoom.cs`) still works when added from the Editor, but the scene then embeds a stand-in `MonoScript` (`grep "^MonoScript:" Assets/Scenes/GetStarted_Scene.unity` finds it) and every reference to that component comes back **null after a runtime scene load** (Retry / next floor / back to menu) and may not load at all in a player build. Plain (non-component) helper classes can share a file.
- **`SaveData` (F118):** additive zero-safe fields need no version bump; anything else = `SaveSystem.Version++` + a `SaveMigrations` case + a fixture test (pattern P1 in `docs/systems.md`). Never rename or remove a `SaveData` field. An unreadable save is set aside as `save.unreadable.json`, never silently deleted. Tests redirect saves with `SaveSystem.DirectoryOverride` (never touch the real PlayerPrefs key).
- **Flicker (F118):** any new flicker / blink / strobe must check `FlashSafety.On` and stay at 3 Hz or slower when it is on; smooth only what is drawn, never gameplay state.
- Keep `.meta` files alongside assets when moving or renaming; scenes and prefabs are text-serialized YAML, so hand edits must preserve GUID references.
- **Never read `Keyboard.current` / `Gamepad.current` / `Mouse.current` — `GameInput` (F119) already ORs `TouchInput`; the recipe for a new action is in `docs/systems.md`.** A bare device read silently strands tablet and gamepad players (and cannot be rebound); the only allowed device sniffers are `GameInput.cs`, `TouchInput.Poll` and `MobilePerformance` (`grep -rn "Keyboard.current|Gamepad.current|Mouse.current" Assets` must return only those). Labels come from `InputGlyphs.Key(GameAction.X, touchLabel)`, never a literal `"E"`. Also: `TouchInput.Pressed`/`Released` intentionally lag `SetHeld` by one frame (see the Touch/tablet bullet in `docs/systems.md`) — don't "simplify" that to same-frame, it exists to make every reader see the edge exactly once regardless of execution order. A menu a gamepad must reach calls `MenuFocus.Keep(root, firstButton)` every frame while it is the top menu.
- **Feature-specific gotchas** (the escape hatch template, `MazeDoor._open`, F74/F77/F87/F92/F93 statics and agent type, pack dressing F79/F85, surface textures and primitive cleanup F88–F90, recorded audio F97, saves and `ShopItem` ints F83) are in `docs/gotchas-features.md` — read the relevant one before touching that feature.
- **Humanoid 3D characters (`neural-3d-asset-pipeline`):** Never build a character from a single full-body neural pass (the head gets only ~6% of pixels/UVs and looks like a blurry mask, while aprons/pockets/props get shrink-wrapped into the body). Always use a dedicated full-frame `1K` close-up head turnaround for `<Character>_Head` (`28K` tris, `2048×2048` UV), build separate 3D sub-meshes for layered garments (`SOLIDIFY` + open-top 3D pocket cavities) and props over `bvh_body`, never use `ShaderNodeBrightContrast` with negative brightness on linear baked albedo, and cut neck/collar seams with `bmesh.ops.bisect_plane` (never vertex deletion).

## Non-Game Assets & Pack History

- The Unity Essentials tutorial itself is gone: `Assets/Tutorials/`, `com.unity.learn.iet-framework`, `UpdateCollectibleCount`, the collectibles UI prefab, and `GameManager`'s win panel are deleted. `Assets/SourceFiles/Models|Animation|Materials|...` are content assets the game still uses.
- The one-off *Remove Tutorial Leftovers* migration has been run and deleted (in git history). `Moving_Platform` / `Wall_Light` prefabs survived because the scene still has instances of them; **KEEP IT LIT > Check Project** lists them.
- `Background_Ambient_Sci-Fi` (scene prefab) is **not** tutorial clutter: `MazeGenerator.TakeOverSceneAmbience` uses its looping clip as the hunter's hum.
- Render settings: URP with `PC_RPAsset`/`Mobile_RPAsset` in `Assets/SourceFiles/Settings/`.
- The player is still the third-person `PlayerRobot.prefab` (two copies) with `FirstPerson = true`; the hunter wears a stripped instance of it too (F102 "Orderly" skin, or the default Sci-Fi Cyborg via `HunterBodyBuilder.Cyborg.cs`), built by **KEEP IT LIT > Build > Hunter Body**.
- **The Adam Character Pack is gone (11 Oct 2026, licence).** `Assets/UnityTechnologies/` was deleted; every body it supplied (hub patients Hilde/Elias, morgue body, Intake silhouette, old NPC/pursuer bodies) is a stripped `PlayerRobot.prefab` (`InteractableKitBuilder.InstantiateRobotNode`); its URP pipeline/renderer/volume assets live in `Assets/SourceFiles/Settings/URP/`. Do not import it again; new characters are Timmy robots (painted with `HunterSkinBuilder`) or Mixamo bodies.
- `Assets/Maze/` keeps only what the wall-button template still uses: `Models/Switch.fbx`, `Prefabs/Switch.prefab`, `Materials/PixPal_URP.mat` (+ its shader graph and textures) and the pack notice, referenced by `InteractableKit/WallButton` and `InteractableKitBuilder.MountKitSwitch`. The `Kit_*` decal/dust prefabs under `Themes/Common/Prefabs` are shared (hub `blood:` keys) and stay.
